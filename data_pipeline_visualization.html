📂 TIDataset — 文本-图像数据集（最核心）

支持的 JSONL 格式

Caption 模式（T2I / 单轮标注）

# data_type = "t2i"
{"image": "imgs/000.jpg", "caption": "a photo of a cat"}

Conversation 模式（多轮理解/对话）

# data_type = "mmu"
{"image": "imgs/000.jpg",
 "conversations": [
   {"from": "human", "value": "What's in this image?"},
   {"from": "gpt",   "value": "A cat."}
 ]}

__getitem__ 处理流程

Step 1: 加载图像

  • 从 image_root + image_field 解析路径
  • PIL.Image.open() → RGB 转换
  • Multi-resolution: 按原图 AR 选最佳 bucket
  • build_image_transform → (3, H, W) in [-1, 1]

Step 2: 文本提取 & Token化

  • Caption 模式: 直接取 caption 字段
  • Conversation 模式 → t2i: 取最后 human turn
  • Conversation 模式 → mmu: 取最后 assistant turn
  • Chat template: tokenizer.apply_chat_template()
  • 普通模式: tokenizer(text) → input_ids

Step 3: 统一序列格式化

  • t2i → format_sequence_gen_qwen2_5()
  • mmu → format_sequence_und()
  • 输出: tt, tl, mp, tm, im 五个张量
  • pad_id 补齐到 max_text_length

Step 4: 构建 images_clip

  • 有 SigLIP: siglip_transform → pixel_values + attention_mask + spatial_shapes
  • 无 SigLIP: clip_image_transform → (3, 384, 384)
  • 纯文本样本: zeros 张量

✂️ EditDataset — 图像编辑数据集

# JSONL 格式
{"raw_image": "imgs/000.jpg",
 "out_image": "imgs/000_edit.jpg",
 "instruction": "make it sunset"}

处理过程

  • 加载 raw_pil + out_pil 两张图
  • 分别 image_transform → [-1, 1]
  • Tokenize instruction 文本
  • format_sequence_gen_qwen2_5_edit() → 双图序列
  • image_mask 仅在 target (第二) 图像上为 1
  • images 返回 torch.stack([raw, target]) → (2, 3, H, W)

🎬 VideoDataset — 视频文本数据集

# JSONL 格式: video 可以是视频文件或帧目录
{"video": "videos/clip.mp4", "caption": "a panda drinking coffee"}
输入类型处理方式
.mp4 / .avi / .mov / .mkv / .webmOpenCV 解码, 均匀采样 num_frames 帧
帧目录 (frame_000.jpg, ...)字母排序后均匀采样 num_frames 帧
Latent 计算: Wan2.2 VAE 下采样 16× (空间) + 4× (时间, causal conv)。 num_image_tokens = (H/16) * (W/16) * latent_T + 1。images 形状 = [C, T, H, W]。

🔤 统一序列（Unified Sequence）布局

所有模态（文本 + 图像）被拼接为单个 token 序列，由 Qwen2.5 自回归 backbone 统一处理。 图像部分通过 modality_positions 张量告知模型在哪里注入视觉特征。

bos/eos boi/eoi img_pad × N text_tokens loss 目标 prompt (不参与loss)

📐 五个核心张量 (tt, tl, mp, tm, im) 详解

所有 format_sequence_* 函数都返回这五个张量，在 Dataset 的 __getitem__ 中被解包为 tt, tl, mp, tm, im，然后存入 dict 的 text_tokens, text_labels, modality_positions, text_masks, image_masks 字段。

缩写变量名dict key类型形状含义
tt text_tokens "text_tokens" LongTensor [max_seq_len] 完整的统一序列 token id，包含 bos/eos/boi/eoi/img_pad/text 所有 token，不足部分用 pad_id 补齐
tl text_labels "text_labels" LongTensor [max_seq_len] LM 训练的标签序列，与 tt 等长。参与 loss 计算的位置 = 真实 token id，不参与的位置 = -100（PyTorch CrossEntropyLoss 默认 ignore_index）
mp modality_positions "modality_positions" LongTensor [num_images, 2] 每行 [start, length]，标记每段图像在 tt 序列中的起始位置和 img_pad token 数量。模型根据此信息在对应位置注入视觉特征（T2I: 1行, EDIT: 2行, MMU: 1行）
tm text_mask "text_masks" BoolTensor [max_seq_len] 标记哪些位置是"真正的文本 token"：1 = 文本 token（包括 bos/eos/boi/eoi/文字），0 = img_pad 或 pad。用于 attention 计算中区分文本和图像区域
im image_mask "image_masks" BoolTensor [max_seq_len] 标记哪些位置需要注入图像特征：1 = img_pad 位置，0 = 其他。EDIT 任务中仅在 target 图像段为 1（raw 图像作为条件输入，其 img_pad 为 0）

具体示例（T2I, N=256, 文本=10 tokens, max_seq_len=512）

tt = [BOS, T₁, T₂, ..., T₁₀, BOI, PAD×256, EOI, EOS, PAD×242]
tl = [-100, -100×10, -100, -100×256, -100, -100, -100×242]  ← 全部 -100（纯条件，不用 LM loss）
mp = [[12, 256]]  ← 图像从位置 12 开始，共 256 token
tm = [1, 1×10, 1, 0×256, 1, 1, 0×242]  ← img_pad 和 pad 位置为 0
im = [0, 0×10, 0, 1×256, 0, 0, 0×242]  ← 仅 img_pad 位置为 1

🎨 T2I (Text-to-Image, Generation)

函数: format_sequence_gen_qwen2_5(), data_type="t2i"

BOS Text Tokens BOI IMG_PAD × N EOI EOS
字段含义值
text_labels全部 -100text 不参与 LM loss，图像 loss 由 flow head 计算
image_mask1 在 img_pad 位置标记需要注入图像特征的 token 位
text_mask1 在非 img_pad, 非 pad 位置实际文本 token 位
modality_positions[[start, len]][len(text)+2, N] — 图像在序列中的位置

🔍 MMU (Multimodal Understanding)

函数: format_sequence_und(), data_type="mmu"

BOS BOI IMG_PAD × N EOI Prompt Tokens Response Tokens EOS
Loss 掩码策略: 仅 Response Tokens 和 EOS 参与 LM loss 计算（text_labels != -100）。 Prompt 和图像部分被 mask 为 -100。

✂️ EDIT (Image Editing)

函数: format_sequence_gen_qwen2_5_edit(), data_type="edit_interleaved"

BOS BOI IMG_PAD × N (raw) EOI Instruction Tokens BOI IMG_PAD × N (target) EOI EOS
关键区别: image_mask 仅在 第二个图像段（target image）为 1。 第一个图像段（raw image）作为条件输入，其 img_pad 位置 image_mask=0。 modality_positions 包含两个条目: [[2, N], [len(text)+4+N, N]]。

🏋️ 训练数据流全景

① 配置解析 (Hydra)

  • 单数据集模式: cfg.data._target_ → 1 个 Dataset → 1 个 DataLoader
  • 多流模式: cfg.data.streams + cfg.data.sampling_weights → N 个 DataLoader → WeightedDataLoaderSampler

② Dataset.__getitem__() → Sample Dict

  • images: Tensor (3,H,W) 或 (2,3,H,W) edit 或 (C,T,H,W) video
  • text_tokens: LongTensor [max_seq_len]
  • text_labels: LongTensor [max_seq_len] (-100 掩码)
  • text_masks: BoolTensor [max_seq_len]
  • image_masks: BoolTensor [max_seq_len]
  • modality_positions: LongTensor [num_imgs, 2]
  • images_clip: Tensor (3, 384, 384) — 或 SigLIP 字段
  • data_type: str | sentence: str

③ DataLoader Collate → Batch Dict

  • 默认 collate: 将各字段 stack 为 batch 维度
  • Multi-resolution: batch_size=1 因为不同样本可能不同分辨率
  • 多流: WeightedDataLoaderSampler 按权重随机选流

④ TunaUnit.compute_loss(batch)

  • dataset_key 解包 (如 "image_t2i", "edit", ...)
  • model_outputs = self.module(data)
  • 内部: prepare_latents_and_labels() → create_attention_mask() → tuna_model()
  • 返回: {"loss": ..., "loss_ntp": ..., "loss_flow": ..., "loss_disp": ...}

⑤ TensorBoard Logging

  • Train Step Loss / ntploss / mseloss
  • Train grad norm
  • Learning Rate (per param group)
  • Train Throughput (tokens/sec)

⚙️ 多流混合采样机制

WeightedDataLoaderSampler

  • 输入: {"image_t2i": DataLoader, "mmu": DataLoader, "edit": DataLoader, ...}
  • sampling_weights: {"image_t2i": 0.5, "mmu": 0.3, "edit": 0.2}
  • 每步按权重随机选一个 DataLoader
  • sync_sampling=True: rank 0 选择后 broadcast 到所有 rank
  • DataLoader 耗尽自动重新初始化 (无限迭代)

🖼️ 多分辨率策略

Dataset 级 (TIDataset multi_resolution=True)

  • 每样本根据原图 AR 选最近 bucket
  • 默认 buckets: [512×512, 448×576, 576×448, 384×672, 672×384]
  • 动态调整 num_image_tokens
  • 需要 batch_size=1

Batch 级 (MultiResolutionIterator)

  • Wraps DataLoader
  • 每 batch 随机选取一个分辨率
  • 对 images, images_clip 统一 resize (bicubic interpolate)
  • 支持 [B,C,H,W] 和 [B,C,T,H,W]

🔍 MMU 推理流程详解 (pipeline.mmu)

① 输入预处理

  • pixel_values → device
  • prompt 前添加 "<image>\n"
  • apply_chat_template() → 对话格式文本

② 序列构建

  • Tokenize 对话文本
  • 找到 <image> token 位置
  • 替换为 [boi][img_pad]*N[eoi]
  • 构造 modality_positions, text_masks, image_masks

③ 模型前向

  • prepare_latents_and_labels()
  • create_attention_mask()
  • tuna_model(...) → input_embeds

④ 生成 & 解码

  • mmu_generate(input_embeds, attention_mask, ...)
  • 支持 do_sample, temperature, top_k, top_p
  • tokenizer.decode() → 文本

🎨 T2I 推理流程详解 (pipeline.t2i)

核心流程: prompts → tokenize → 序列构建 → tuna_model 前向获取 hidden states → flow matching 扩散去噪 → VAE decode → PIL images。
关键参数: num_inference_steps, guidance_scale, sampling_method, time_shifting_factor, noise_level。
